# 自用：把「电闹播放器 + 响度归一」装进 Edge（逐步操作）

> 目标：在 Edge 里用上带响度归一的电闹播放器。
> 全程大约 10–20 分钟（大头是第一次 `yarn install` 下载依赖）。
> 下面每一步都写了「应该看到什么」，对不上时直接跳 §9 的排查表。

---

## 0. 前置：确认机器上有这些

打开 PowerShell（开始菜单搜 `PowerShell`），逐条输入：

```powershell
node --version      # 需要 v20 以上（推荐 22 LTS）
git --version       # 任意版本
python --version    # 可选，但强烈建议有（构建最后一步用它拷 ffmpeg）
```

缺 Node → https://nodejs.org （装 LTS 版，安装时勾选 "Add to PATH"）
缺 Git → https://git-scm.com/downloads
缺 Python → https://www.python.org/downloads/ （同样勾选 Add to PATH）

Edge 是系统自带的，不用装。

## 3. 造 `.env`（**必需**，不是可选）

```powershell
Copy-Item .env.example .env
```

为什么要这一步：`webpack.config.js` 里 `dotenv-webpack` 开了 `safe: true`，**没有 `.env` 会直接构建失败**。
拷出来的占位值（`DROPBOX_KEY=DROPBOX_APP_KEY` 这种）完全够用，它只影响「云同步」那几个后端
（Dropbox / Gitee / GitHub / 个人云），**不影响播放和响度归一**。

如果你想让云同步真能用，就填自己的 Key；不填就当这些按钮点了不生效，其它一切正常。

## 4. 装依赖

项目用的是 **Yarn 4**（`package.json` 里写了 `packageManager: yarn@4.7.0`）。Node 20+ 自带 corepack：

```powershell
corepack enable
yarn
```

**应该看到**：一堆 `+ xxx` 的安装输出，最后 `Done in xxxs`。

> **如果 `corepack enable` 报权限错误**（Node 是系统级安装时常见）：
> 用管理员身份重开 PowerShell 再执行一次；或者跳过 enable 直接用
> `corepack yarn install` / `corepack yarn build`。
>
> **如果机器上根本没有 corepack 命令**：`npm i -g corepack` 之后重试；或者用官方 CDN 的 yarn：
> ```powershell

**如果这一步很慢**：正常，依赖里包含 `@ffmpeg/core`（wasm，几十 MB）。换国内镜像可以明显提速：


## 5. 构建

```powershell
yarn build
```

它做两件事：`webpack --env prod` 打包 → `python3 ./scripts/moveFFMpeg.py --prod` 把 ffmpeg 的 wasm 拷进 `build/js`。

**应该看到**：`webpack 5.x compiled successfully`（会有若干 warning，正常），最后无 error。

> ⚠️ **最常见的坑**：脚本里写的是 `python3`，Windows 上通常只有 `python`。如果 `yarn build`
> 在最后报 `python3 不是内部或外部命令`，手动补这一步就行：
> ```powershell
> python .\scripts\moveFFMpeg.py --prod
> ```
> （或者把 `package.json` 里 `moveFFMpeg.py --prod` 前面的 `python3` 改成 `python`。）

构建完自检（三样都必须有）：

```powershell
dir build\manifest.json, build\serviceWorker.js, build\js\ffmpeg-core.wasm
```

再确认 manifest 里是 MV3：

```powershell
Select-String -Path build\manifest.json -Pattern 'manifest_version'
```

**应该看到**：`"manifest_version": 3,`

## 6. 加载进 Edge

1. 地址栏输入 `edge://extensions/` 回车；
2. 左下角把 **开发人员模式** 打开；
3. 点 **加载解压缩的扩展**；
4. 选 **`D:\code\noxplayer\build`** 这个文件夹（⚠️ 选 `build`，不是仓库根目录；选错会报
   「清单文件缺失或不可读」）；
5. 列表里会出现「电闹播放器」。

**接着**：点一下工具栏上的扩展图标（如果没有，点地址栏右边的拼图/扩展按钮 → 固定它），
它会**新开一个标签页** —— 播放器就跑在这个页面里（这是它原本的设计）。

> ⚠️ 这个未打包版和商店版是**两个不同扩展**（ID 不同 → 数据也各自独立）。
> 也就是说商店版里的歌单不会出现在这里。两个选择：
> ① 在商店版里用「设置 → 同步/备份」导出，再把数据导入新扩展；
> ② 直接卸载商店版，只留这一个。
> 两个同时开着不会打架，但没必要。

> ⚠️ 别删也别移动 `D:\code\noxplayer\build` 目录 —— Edge 记住的是这个路径，移走扩展就失效了。

## 7. 打开响度归一

播放器页面里：

1. 顶部「**我的歌单**」那一行右侧有三个图标：随机播放、**齿轮（播放器设置）**、问号（帮助）；
2. 点**齿轮** → 弹出「播放器设置」；
3. 停在「**设置**」标签页（另一个标签是「工具箱」）；
4. 往下滚，找到「**响度归一（整段测量 + 固定增益）**」区块（就在 `r128gain` 那个勾选框下面）；
5. 勾上它；「响度档案」保持默认 **标准（-14 LUFS）** 就行；
6. 建议保持勾选「提前测量下一首」。

同区块里可以调：目标响度、最大提升、最大衰减三个滑条（拖了会自动切到「自定义」档案）、
「旁路」勾选框、「清空测量缓存」按钮，以及一行状态显示
（`命中缓存 · sidx · 实测 -18.7 LUFS · 目标 -14 LUFS · 增益 4.7 dB · 输出 gain-node`）。

关掉对话框，随便点首歌播放。**第一次**大概几百毫秒后音量会平滑落到目标值；
**同一首再播**就是瞬时到位（命中缓存）。

## 8. 验收 / 自己核对效果

### 8.1 看它到底做了什么

在播放器标签页按 `F12` → Console，然后：

```js
noxLoudness.getLastStatus()
```

**应该看到**：

```js
{ songId: '137649199', stage: 'applied', engine: 'sidx', measuredLufs: -18.72,
  targetLufs: -14, gainDb: 4.72, segments: 12, mode: 'gain-node', reason: undefined }
```

- `measuredLufs`：这首歌实测的整段集成响度；
- `gainDb`：施加的**那一个**固定增益；
- `mode`：`gain-node` 表示已经通过 Web Audio 接管（最理想）；`volume` 表示降级成了只能衰减的元素音量；
  `off` 表示还没接管或功能没开。

控制台里搜 `loudness` 还能看到流程日志：

```
loudness: AudioContext ready (48000Hz, state=running)
loudness: <audio> is now routed through the loudness gain node
loudness: 歌名: -18.72 LUFS -> target -14 LUFS, gain 4.72dB (sidx)
```

### 8.2 你的两条验收标准怎么测

**① 切换不跳变**：找两首响度差很大的（比如老 MV 很响、播客/直播录屏很轻），都丢进歌单，
连播 3–5 次。切换瞬间应该**听不出跳变**。
想量化就在切换前后各跑一次 `noxLoudness.getLastStatus()`，看两首的 `gainDb` 是不是都在几秒内就到位。

**② 动态不被压平**：在**同一首**里挑一段安静的、一段爆炸/高潮：

- 按 `Shift+B` 旁路（听原声）→ 再按一次恢复（归一）；
- 两种情况下的「安静段 vs 高潮段」音量差应该**一样大**，只是整体平移了一个固定量。

再硬核一点（确认增益是常数，不是动态跟随）：

```js
// 在安静段执行一次，在高潮段再执行一次，两次应该几乎相同
noxLoudness.engine.getGainValue()
```

如果发现 `mode` 是 `volume`（降级模式），那它只能衰减、不能提升 —— 把控制台日志发我看看是哪一步没接管成功。

## 9. 排查表

| 现象 | 原因 / 处理 |
|---|---|
| `yarn build` 报 `Error: Failed to load ./.env` 或 dotenv 相关 | 没做 §3，`Copy-Item .env.example .env` |
| `yarn build` 最后报 `python3 不是内部或外部命令` | 见 §5，改 `python` 或手动跑 `python .\scripts\moveFFMpeg.py --prod` |
| webpack 报 `Cannot find module '@APM/...'` / `azusa-player-mobile` | 没做 §2 的子模块 |
| `corepack enable` 权限错误 / 没有 yarn | 见 §4 的两种后备方案 |
| Edge 报「清单文件缺失或不可读」 | 加载时选错目录了，要选 `build` |
| 扩展加载了但**完全没声音** | 打开播放器标签页 F12 看是否有 `createMediaElementSource failed` 或 `AudioContext is suspended`；后者是浏览器自动播放策略，先点一下页面任意位置再播放 |
| 设置里有「响度归一」但状态一直是 `off` | 说明没接管成功：看 `noxLoudness.engine.getMode()` 与控制台 `[loudness]` 日志 |
| 状态显示 `failed` | 测量失败（网络/解码）。先用同区块的「测量方式」切到 **ffmpeg 全片** 验证是不是抽样路径的问题 |
| 云同步按钮点了没反应 | `.env` 里是占位 Key，属于预期 |
| 每次启动 Edge 提示「正在使用开发人员模式扩展」 | 未打包扩展的正常提示，点掉即可；想彻底没有就得打包上架 |
| 关了播放器那个标签页音乐就停了 | 设计如此：播放器就是那个页面，别关 |
